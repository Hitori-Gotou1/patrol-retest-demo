# 站主简明操作

本机创作可直接使用。两项后端迁移已由站主执行，升级前端尚待授权发布。以下为升级版的操作方式。

1. 数据库升级文件为 `supabase/gallery-upgrade.sql` 与 `supabase/migrations/20261114_device_sync.sql`，本次均已执行，无需重建项目或初始化 `gallery.sql`。两项都有独立回滚脚本和数据影响说明。继续使用现有站主 UID 白名单、`gallery-uploads` 存储桶和两项 GitHub 公开构建变量。不要将数据库密码或 service_role key 放入 VITE 变量。
2. 打开 `/#/manage-gallery`，使用既有站主账号登录。「批量上传」可多选/拖入；先逐图或批量填写角色、分类、标签和作者来源，再开始。手机一张、桌面最多两张同时处理。失败图单独重试，尚未开始的任务可取消。上传中离开会提醒；文件本身不作为长期草稿保存。
3. 「已发布图片」中搜索、分页和筛选，编辑资料及排序值；较小值靠前。下架与恢复保持图片编号，因此原收藏和分享仍能识别。下架隐藏列表，不撤销原来的公开文件地址。仓库静态图到仓库维护。
4. 「主题合集」中写标题/简介，按顺序加入图片编号，选封面后保存。图片可同时进入多个合集；删合集不会删图。静态策展示例维护在 `src/data/galleryCollections.js`；云端新合集从工作台维护。静态例有可抓取分享页，云端动态合集使用可打开的 Hash 分享。
5. 模板集中在 `src/room/templates.js`。每套应有固定ID、主题名、说明、适用工具与完整有效payload；预览从同一payload渲染。维护后运行 `node tests/mobile-templates.test.js` 并在对应编辑器实际应用、编辑、保存、导出。模板与用户作品分开；不要修改作品架24版/3MiB限制。
6. 分享精选维护在 `src/data/featuredWorks.js`，只放已确认可以公开的内容。构建自动生成静态分享页；私人作品和云端同步数据不会自动进入公开清单。
7. 「搜索与设置 → 安装、离线与跨设备同步」管理下载玩法和版本。清理离线资源不会清作品/草稿。同步使用独立访客账号，首次连接先预览合并，冲突明确选择。专用隔离账号的真实权限与多设备验收已通过；新部署仍须保持原RLS和修订RPC，不能开放表的直接写入。

发布仍沿用 GitHub Actions：`npm ci` → `npm test` → `npm run build` 与已有路由/图库/活动室检查 → Pages。当前 `dist/` 与 `release/` 是待授权产物，**不要直接推送 main 来试运行**，因为这会触发现有生产发布流程。获授权并完成真实后端验收后才发布，并检查线上 `build-info.json`、新路由、静态分享和离线更新。

详细配置和回滚：[图库](gallery-admin.md)、[同步](offline-sync.md)。验证与逐项状态：[交付说明](delivery.md)。
