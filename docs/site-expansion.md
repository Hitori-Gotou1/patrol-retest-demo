## 来源与资料更新

三张既有原创 / AI 图形的制作说明记录在 `src/data/gallery-attributions.json`。另外51张站主收藏没有经过确认的原作者信息，按站主反馈“无”保留为“原作者待确认”，不推测作者、原作链接或授权。来源整理表只保存在当前浏览器；公开档案由站主核对导出的 JSON 后更新仓库并发布，不会把访客填写的内容自动公开。

日历来源在 `src/data/calendar.js`，核对日期为2026-11-13。过去的演出明确显示已过去；没有公告的时间不推测。巡礼地址以运营方链接为依据。取景元数据来自 Anitabi 公共接口，截图及贡献者原始链接记录在 `src/data/pilgrimage-points.json`，页面附署名和 CC BY-NC-SA 4.0 链接。示意图不表示真实比例或步行距离；地图导航打开真实地点搜索。截图服务不可用时提供原站对照入口。

## 数据兼容

作品架仍使用版本1、最多24个版本和3MiB总量；新标签和置顶为可选字段，旧备份可以导入。继续编辑旧作品会先保存不同的当前草稿，导入合并记录，不替换编辑页草稿。演出项目保存各组成部分的副本；原作品更改或移除不影响项目内快照。挂墙画面同样是独立副本。较大的项目可直接导出完整 JSON，不必受作品架单件大小上限约束。

演出只在主动点击播放后解锁 Web Audio。隐藏页面、离页或关闭全站音效会停止声音和时间轴，迟到的音频解锁不会重新启动播放。

## 启用全站汇总

本次发布默认使用**本机计数**，不发送统计请求。当前执行环境没有 Supabase 数据库管理权限，不能替站主应用 SQL；因此线上看板会明确显示全站汇总尚未启用。

站主以后可以在现有 Supabase 项目 SQL Editor 中执行 [`supabase/analytics.sql`](../supabase/analytics.sql)，沿用 `gallery.sql` 中的站主白名单。然后将 GitHub Actions 的仓库变量 `VITE_SITE_ANALYTICS` 设置为 `enabled`，保留已有 `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY`，重新构建发布。

接口仅记录 UTC 日期、白名单内容编号、打开 / 完成 / 导出计数，不包含设备编号、身份、搜索词或作品内容。匿名客户端只能调用递增函数；读取汇总需要已有图库站主账号和 RLS 白名单。完成动作包含完成活动及新存作品，计数不是去重访客数。重复导入本机统计备份时同日期同项目取较大值，避免重复累加。访客可在顶栏工具关闭记录。
