入口：`/#/room/play`。新板块各自按需加载，活动室首页提供新板块、小冒险、创作角落与全部分类，旧地址继续可用。

## 操作、存档和音频

跳跃用方向键 / A D 移动，空格按住蓄力、松开起跳，空中可以补跳一次，J 冲刺。至少收集三枚音符到终点才解锁下一关。弹珠用方向键 / A D 控制挡板，空格蓄力发射，N 轻推（冷却三秒）。点击台面可获得键盘焦点；两者都有触屏按钮，采用固定 120 Hz 物理步长。切换窗口、页面隐藏和离开路由都会暂停。

新数据保存在 `hitori-room:<板块 id>:v1`。灯光背景另存 `hitori-room:stage-background:v1`。刷新不会把跳跃、弹珠或忙碌营业恢复为自动运行。浏览器禁止存储时本次仍可游玩，界面会说明保存失败。跨设备可以带走 PNG / WAV / 灯光 JSON；不提供账号云存档。

短音效沿用全站互动音效开关。混音的四轨使用本站原创确定性波形，点击后才创建实时音频；A/B 不覆盖自己的设置。导出通过离线音频上下文渲染，不需要播放。循环混音与灯光同步遵守全站静音、音量、页面隐藏和路由离开清理，包括延迟 `resume()` 返回的竞态。

## 接龙发布

公开投稿链接预填 GitHub Issue，访客需要自行登录并确认提交，网站不会替访客发送内容。投稿带 `hitori-relay`，站主或具备 admin / maintain / write / triage 权限的审核者添加 `hitori-approved` 才纳入审核记录。内容、昵称和长度严格校验；审批事件还会重新读取 Issue 的当前正文、标题、状态与标签。

`.community/relay-ledger.json` 记录已审核的句子，`public/community/relay-stories.json` 是展示快照。每个故事保留已经发布的接续；下一句必须匹配故事、上一条 Issue 编号和句序。多个候选均已审核时，优先接较小 Issue 编号；已有发布分支不会被迟到的候选替换。编辑、关闭、重开、删除或移除审核/投稿标签会撤回该句，断开的后续句子也会退出展示，必须重新接上有效分支。

不同 Issue 的更新使用 GitHub 文件 SHA 乐观重试。先持久化审核记录，再读取快照 SHA、读取最新记录并生成快照，避免并行审批用旧记录覆盖新故事。失败任务重跑可以继续发布已写入的审核记录。GitHub Token 提交后会显式触发原有 Pages 工作流，仍通过构建、图库、路由与活动室检查。六句未满时网站快照只包含最后一句；GitHub 投稿和仓库内审核记录始终公开。

本机练习不使用审核记录，不伪装成其他访客，也不会自动上传。

## 验证

```sh
npm run build

```

浏览器测试自带临时静态服务器，支持 `HITORI_CHROMIUM_EXECUTABLE` 指定系统 Chromium。测试覆盖实际滑块拖动、拼图拖放、漫画角色拖动、画布绘画与撤销、PNG 尺寸、WAV 采样、声音清理、接龙投稿链接与本机六句揭晓，以及 1440 / 390 / 320 像素布局。测试拦截外部请求，不创建真实投稿。
